PORTFOLIO / MAINTENANCE PLAN

Keep it growing.

A practical plan for keeping Diane Angeline M. Valencia’s portfolio accurate, accessible, and up to date.

Before submitting

  • Review the About section each term. Keep the BSCS year level, Accountancy-to-tech background, interests, and skills current. Support technical skills with examples of actual work.
  • Review all seven projects. Keep the two live web project links working. Add the barangay database technology, schema, scope, and personal contribution when available. Keep Leo and Angela’s wedding details and preview link reserved until ready to share. Update SellSight AI as development progresses; do not describe planned features as completed.
  • Keep the Best Group Presenter PDF and HTML Essentials information accurate. Add remaining certificates with their titles, issuers, dates, and readable files or verification links. The HTML Essentials badge and certificate screenshots refer to one credential and should not be counted twice.
  • Test the GitHub, LinkedIn, Facebook, Wokwi, and Tinkercad links from the deployed site. Optionally add a professional email address for direct enquiries.
  • Review spelling, grammar, privacy, and the accuracy of every claim.
  • Confirm the instructor can access the deployed URL. Enable GitHub Pages from main / (root), wait for deployment to succeed, and open the public Pages URL while signed out before submission.

After each project, certificate, or activity

Update the relevant entry within one week of completion. Keep Stanford Code in Place 2026 and the Meta Global AI Developer Hackathon marked ongoing until completion is confirmed. Add completion dates and proof before moving them into earned credentials. For each project, explain the problem, your contribution, the tools used, and what you learned. Add one specific outcome and useful screenshots with descriptive alternative text. For certificates, record the issuer and date and include a verifiable credential when available.

Monthly

  • Check every project, certificate, navigation, and contact link.
  • Test the mobile menu, collection filters, and project dialogs using both a pointer and a keyboard.
  • Review the site on a phone and a desktop, and test Chrome, Safari, Firefox, and Edge. Check reading order, contrast, and text at 200% zoom.
  • Check for loading errors and keep new images compressed. Add explicit image dimensions to avoid layout shifts.

Each school term

Refresh the biography, review the strongest work, and update the skills section with evidence from recent projects. Review page titles, descriptions, alternative text, and contact details. Archive outdated material and review the public information before sharing.

Publish and back up

Keep changes in version control, review them, and publish the tested version. The portfolio uses HTML, CSS, and JavaScript without a build step. GitHub Pages serves the root folder of the main branch. Keep index.html at the repository root and retain the supplied relative asset paths. See GITHUB-PAGES-SETUP.md in the repository for publishing instructions.

After deployment, confirm the intended URL loads for the intended audience. If a change fails, restore the last working version. Keep local copies of original project screenshots and certificates.
