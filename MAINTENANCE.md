# Maintenance plan

Owner: Diane Angeline M. Valencia. Review this plan each school term.

## After a project or certificate update

Within one week, update the relevant card, dialog description, live/repository links, status, and screenshots. Describe the problem, your contribution, tools, outcome, and what you learned. Move an ongoing item into completed work only after completion is confirmed.

## Monthly

- Test all menu, filter, dialog, certificate, profile, and external project links.
- Check the live website at phone, tablet, and desktop widths, including 320px and 200% zoom.
- Check for missing images, overflow, spelling errors, and failed external links.
- Keep certificate filenames and folder paths stable, or update every corresponding HTML link.
- Confirm anonymous visitors can still open the public Pages URL.

## Each term

Refresh the year level, biography, skills, and strongest work. Review metadata, accessibility, and performance. Archive outdated material and review the public information before sharing.

## Publishing and rollback

Keep reviewed changes in `main`. GitHub Pages serves the root folder and redeploys after commits. Confirm the deployment succeeds before submitting a URL. If a change breaks the site, restore the previous working files from GitHub history and commit the restoration.

Keep original project and certificate files backed up locally. The human-readable version of this plan is `maintenance.html`.
